# 0.1.0b28 — Accept a flat top at the opening limit; drop the fixed timeout pause

A radiator that warms slowly (e.g. heat loss from an open window) can still be approaching a real plateau when the maximum opening duration arrives. Previously this always counted as a timeout: the stale reference was kept and the valve paused for a fixed multiple of the open duration before recalibrating, so a room could cycle through the same failed calibration repeatedly.

**Accept a flat top at the limit.** If a plateau candidate exists when the maximum opening duration is reached and produces a valid compensated cutoff, it can be accepted before the normal confirmation interval has elapsed and the pulse closes normally (`plateau_at_limit`) — the reference updates as it would from an ordinary `plateau` close. A missing or rejected candidate counts as a timeout (`maximum_open_duration`). A gently falling top can still qualify within the detector tolerances; flatness alone is insufficient.

**No more fixed timeout pause.** A genuine timeout now closes as an ordinary pulse: room demand, the cooling gate, the restart temperature and the room's maximum duty cycle decide when it may reopen, exactly as for any other close. There is no separate four-times-open-duration pause. At 33% duty, a 15-minute timeout adds about 30 minutes 27 seconds of minimum closed time. With no duty limit there is no additional timed pause, but room demand, cooling readiness and normal input and valve checks still apply. The next pulse after a timeout still recalibrates (`retry_calibration` persists through a restart). Window PWM and input-failure maintenance pulses keep their own independent timing, unaffected by this change.

No new entities or options. Existing compatible calibration and restart thresholds remain usable. As before, a pending duty pause is not restored after restart. New duty selectors use a room-based entity ID; existing registry IDs are unchanged.
