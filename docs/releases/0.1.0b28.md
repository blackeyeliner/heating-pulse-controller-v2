# 0.1.0b28 — Accept a flat top at the opening limit; drop the fixed timeout pause

A radiator that warms slowly (e.g. heat loss from an open window) can still be approaching a real plateau when the maximum opening duration arrives. Previously this always counted as a timeout: the stale reference was kept and the valve paused for a fixed multiple of the open duration before recalibrating, so a room could cycle through the same failed calibration repeatedly.

**Accept a flat top at the limit.** If a flat window is already under confirmation when the maximum opening duration is reached, it is accepted as the plateau and the pulse closes normally (`plateau_at_limit`) — the reference updates as it would from an ordinary `plateau` close. Only a top that is still rising or falling when the limit arrives counts as a timeout (`maximum_open_duration`).

**No more fixed timeout pause.** A genuine timeout now closes as an ordinary pulse: room demand, the cooling gate, the restart temperature and the room's maximum duty cycle decide when it may reopen, exactly as for any other close. There is no separate four-times-open-duration pause. At 33% duty, a 15-minute timeout is followed by at least 30 minutes closed; with no duty limit, only the restart temperature applies, so a radiator that never warms can reopen almost immediately. The next pulse after a timeout still recalibrates (`retry_calibration` persists through a restart). Window PWM and input-failure maintenance pulses keep their own independent timing, unaffected by this change.

No new entities or options. Existing saved calibration, restart gate and duty-pause state are unaffected by the upgrade.
