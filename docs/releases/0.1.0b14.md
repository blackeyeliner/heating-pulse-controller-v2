# Beta14: native room thermostat and persistent control intent

Adds a native climate entity, independently persisted target/heat-off request and logical valve sensor. Fresh installations no longer need a template/generic thermostat, dummy switch or numeric helper. Existing entries opt in using adopt_thermostat while disabled; current mode/target are captured. An optional legacy valve helper can remain solely as a history mirror.

Bundles a thermostat card using HA standard controls: orange confirmed heating, blue idle, grey off/uncertain. No separate frontend installation. The integration registers its versioned JavaScript asset and supports parallel room setup.

Enabled control now survives compatible restart/reload/update. Explicit off persists. Startup checks valve availability, ownership, valid request and fresh reports, confirms closure, then evaluates demand anew. Missing non-actuator inputs eventually use existing bounded fallback PWM rather than permanently preventing heat. Interrupted pulses are never resumed. A critical valve incident still disables only its room and requires reset/re-enable; the ten-minute reconnection grace and backup AC policy are unchanged.

Per-room calibration/open-duration limits and tuning are unchanged. Valve-position and HVAC action describe confirmed commands, not measured flow or physical stem motion. Existing entity IDs can be handed over to preserve dashboard and automation references.
