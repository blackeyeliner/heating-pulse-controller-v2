A clean restart used to replace a confirmed adaptive cooling threshold with the conservative room +3 °C startup gate, unnecessarily delaying the next requested pulse. Beta 7 preserves a validated cooling episode across a short restart/reload.

- Save confirmed peak, frozen threshold/fraction and timestamped observations only on clean shutdown after successful valve closure. Consume the checkpoint on the next start so it cannot survive into an unrelated later crash.
- Restore only after fresh reports, a closed window and closed TRV limits, with matching settings/bindings, a short gap within the radiator timeout, and no contradictory radiator warming. Current demand and cooling readiness are recalculated; control still starts disabled.
- Interrupted pulses, calibration, unconfirmed settling, window PWM and fault states are not resumed. Invalid/missing checkpoints use the original startup gate. Legacy calibration storage remains compatible.
- Expose `restore_status` on Restart temperature for verification. Existing beta 6 window PWM/protection behaviour is unchanged.

Validation covers clean reload with real HA storage and entity platforms, restored gate versus fresh demand, rejection of warming/old/corrupt data, settings/entity/window changes, unknown startup feedback, failed closure, and the previous regression suite.

Earlier versions did not save cooling state; this feature becomes available after beta 7 records a confirmed episode. It does not reconstruct an already lost peak from the current surface temperature.
