# Beta24: physical TRV controls drive the native room thermostat

Turning the TRV out of Off into manual Heat enables the native room controller at the selected4–35 °C target. Further rotation changes the room target. A physical Off or Auto transition disables native heat and restores firmware Off/frost protection; the built-in Auto schedule is not adopted. On this hardware a short press in Off only wakes the display, with no mode change: enabling is by rotation. A press that changes manual Heat to Auto acts as Off.

Native mode/target changes also reach the TRV display between pulses. Closed limits are established before changing a firmware mode, so display synchronisation alone does not open the valve. Room demand, cooling gates, window/PWM policy, ownership and fault guards still determine pulse heating.

Expected mode/setpoint feedback from our own writes is filtered before accepting external changes as requests. Availability/startup, status-only reports and autonomous occupied-setpoint updates in Off cannot enable Heat. Requests are coalesced briefly; Off inhibits in-flight opening immediately and cancels a pending rotary enable. Unload prevents delayed gestures from changing stored intent. External changes to the bound physical climate entity use the same path as local controls.

Fifteen new tests cover physical mode/target changes, range endpoints, command echoes, frost/schedule updates, idle display sync, unload and pending/in-flight Off. Existing Antifreeze presentation and logical0/5 graph are unchanged. No tuning, frost-temperature or AC changes. Real hardware rotation/press verification follows installation; do not mistake simulated service feedback in tests for a completed physical test.

MQTT bindings subscribe to the exact discovery state topic and use the retain flag directly. Retained messages only establish a baseline; the derived HA state callback cannot bypass that filter. Discovery that is still loading is retried once a minute. `physical_controls` on the native climate reports mqtt, waiting_mqtt or the non-MQTT state adapter. Optional MQTT startup ordering is explicit. Additional tests cover retained messages, live MQTT command echoes and subscription retry/unload.

Supersedes the unreleased beta23 draft, which was never installed.
